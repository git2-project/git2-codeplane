# Codeplane version notes — 2026-10-26

**Audience:** every git2 lane (CI, Dash, Console, Deploy) and their coding agents.
**Scope:** git-svc's first gRPC contract (`git.v1`) and its repository storage are ready for review. You can create, get, find, list and delete repositories, and every create and delete records an event. The `git_svc` schema comes as a migration PR on git2.

**Canonical reference:** [proto/git/v1/repository.proto](../../../../proto/git/v1/repository.proto) and [proto/git/v1/events.proto](../../../../proto/git/v1/events.proto). Every RPC, message and field is documented there, including validation rules and error codes. The reasons are in [docs/decisions/](../../../decisions/).

**Breaking?** No. This is the first version.

## 🟢 NEW — `git.v1.RepositoryService`

Five RPCs on git-svc's gRPC port (9090 by default). git-svc does not check permissions: the caller (gateway, dash-api, admin-api) checks them before calling.

| RPC | Input → output | Errors |
|---|---|---|
| `CreateRepository` | `owner_id`, `name`, optional `default_branch` (default `main`) and `description` → `repository` | `INVALID_ARGUMENT`, `ALREADY_EXISTS` |
| `GetRepository` | `id` → `repository` | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `FindRepository` | `owner_id`, `name` → `repository` | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `ListRepositories` | `owner_id`, `page_size`, `page_token` → `repositories`, `next_page_token` | `INVALID_ARGUMENT` |
| `DeleteRepository` | `id` → empty | `INVALID_ARGUMENT`, `NOT_FOUND` |

**Identity and names:**
- IDs are UUID strings. A malformed ID is `INVALID_ARGUMENT`, not `NOT_FOUND`.
- Names are 1–100 characters of `A-Z a-z 0-9 . _ -`, do not start with `.` or `-`, and do not end with `.git`.
- A name is unique per owner, compared case-insensitively. `FindRepository` also ignores case.

**Errors:**
- `ALREADY_EXISTS` means the owner already has a live repository with that name, in any letter case.
- `INTERNAL` never carries details; git-svc logs them.

**Lists and deletes:**
- `ListRepositories` is sorted by name. `page_size` 0 means 50, values above 100 mean 100. `page_token` is opaque and only valid for the same `owner_id`.
- A deleted repository disappears from Get, Find and List at once, and its name can be reused right away. It cannot be restored through the API.

A call with grpcurl, from the devcontainer, with `GIT2_GITSVC_DEV=true`, which turns on reflection:

```sh
go tool -modfile=tools.mod grpcurl -plaintext \
  -d '{"owner_id":"<owner-uuid>","name":"payments"}' \
  localhost:9090 git.v1.RepositoryService/CreateRepository
```

```json
{
  "repository": {
    "id": "<repository-uuid>",
    "ownerId": "<owner-uuid>",
    "name": "payments",
    "defaultBranch": "main",
    "createdAt": "2026-10-26T09:00:00.123456Z",
    "updatedAt": "2026-10-26T09:00:00.123456Z"
  }
}
```

From Go, use the generated code committed in this repo:

```go
import gitv1 "github.com/git2-project/git2-codeplane/gen/go/git/v1"

client := gitv1.NewRepositoryServiceClient(conn)
resp, err := client.FindRepository(ctx, &gitv1.FindRepositoryRequest{OwnerId: ownerID, Name: "payments"})
// status.Code(err) == codes.NotFound when the owner has no such repository
```

`go get github.com/git2-project/git2-codeplane@<version>` works once the first tag is cut after this work is merged. Until then, use a commit hash.

## 🟢 NEW — Events in `git_svc.outbox`

- **`git.v1.RepositoryCreated`** and **`git.v1.RepositoryDeleted`** are written on every create and delete, in the same transaction as the change.
- **`git.v1.RepositoryPushed`** is defined but **not emitted yet**. It starts with push over HTTPS (W2–W3).
- **Nothing delivers the events yet.** The relay is codeplane's W2 work (WBS-1.3). Delivery will be at least once, so drop duplicates by `event_id`.

| Column | Content |
|---|---|
| `id` | `BIGSERIAL`, the relay's reading order |
| `event_id` | `UUID`, the event's own ID |
| `aggregate_type` | `repository` |
| `aggregate_id` | the repository ID |
| `event_type` | full protobuf message name, e.g. `git.v1.RepositoryCreated` |
| `payload` | `JSONB`, the message in canonical protobuf JSON |
| `created_at` | when the row was written |
| `published_at` | `NULL` until the relay has delivered the event |

```json
{"id": "<repository-uuid>", "ownerId": "<owner-uuid>", "name": "payments", "occurredAt": "2026-10-26T09:00:00.123456Z"}
```

Decode the payload with `protojson.Unmarshal` into the type named by `event_type`.

## ℹ️ FYI — The `git_svc` schema is a migration on git2

`migrations/002_git_repositories.sql` creates the `git_svc` schema with the `repositories` and `outbox` tables. It follows git2's rules: plain SQL, first line a `-- ` comment, applied by the GitHub Action after the merge.
- git-svc never changes the schema. It checks at startup that its tables exist and refuses to start otherwise.
- The number `002` holds only if no other migration is merged first; otherwise we renumber before the merge.

Details: [ADR 0006](../../../decisions/0006-database-migrations.md).

## ℹ️ FYI — Answers to the CI lane's assumptions

| ID | Answer |
|---|---|
| A-02 | The event's shape is fixed. One `RepositoryPushed` per push lists every changed ref in `ref_updates`: `old_sha` all zeros means created, `new_sha` all zeros means deleted, and `forced` means not a fast-forward. Delivery is at least once, with `event_id` for deduplication. How it reaches `TriggerPipeline` is decided with the relay (WBS-1.3, W2). |
| A-03 | Planned, not in the contract yet: `CommitService` (W2–W3) returns a file's content at a commit. |
| A-04 | Planned, not in the contract yet: a server-streaming RPC that returns a commit as a tar archive (`git archive`), next to `CommitService`, before W4. |
| A-12 | Confirmed: git-svc stores and returns IDs only (ADR 0002). |
| A-13 | Confirmed, with more columns than assumed (table above). If `ci_svc.outbox` uses the same columns, one relay can serve both. |
| A-14 | Done: codeplane uses Go 1.26 and `POSTGRES_DSN` (ADR 0010). |
