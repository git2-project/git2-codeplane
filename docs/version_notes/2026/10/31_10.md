# Codeplane version notes — 2026-10-31

**Audience:** Deploy (gateway, Compose, Helm), CI, and their coding agents.
**Scope:** git-svc now serves `git clone`, `git fetch` and `git push` over Git's smart HTTP protocol, on a new HTTP port that also has `/healthz` and `/readyz`. Every push that changes refs records `git.v1.RepositoryPushed`.

**Canonical reference:** [ADR 0012](../../../decisions/0012-git-over-https.md) for the HTTP side, and [proto/git/v1/events.proto](../../../../proto/git/v1/events.proto) for the event.
These are the source of truth; this note only summarizes the change.

**Breaking?** No. The port is new, and the event was already defined.

---

## 🟢 NEW — Git over HTTP on port 9080 (for the gateway)

git-svc listens on `GIT2_GITSVC_HTTP_ADDR` (default `:9080`). The gateway routes `/<owner>/<repo>.git/*` there as `/<repo-id>.git/*`, as its contract v0 says.

| Route | Purpose |
|---|---|
| `GET /<id>.git/info/refs?service=git-upload-pack` | refs, for clone and fetch |
| `POST /<id>.git/git-upload-pack` | clone and fetch |
| `GET /<id>.git/info/refs?service=git-receive-pack` | refs, for push |
| `POST /<id>.git/git-receive-pack` | push |

**What git-svc expects from the gateway:**
- `X-Git2-User-Id`: the signed-in user's ID. **Required for pushes** (`403` without it); optional for clone and fetch.
- `X-Request-Id`: logged with each request.
- The client's `Content-Type`, `Content-Encoding` and `Git-Protocol` headers, passed through unchanged. `Git-Protocol` is what turns on protocol v2.
- Bodies streamed in both directions, never buffered. A clone or push can take minutes and hundreds of megabytes.

git-svc does not check permissions: the gateway decides who may read or push before it forwards the request.

**Answers.** Errors are plain text, which git shows to the user as `remote: …`.

| Status | When |
|---|---|
| `403` | push without a valid `X-Git2-User-Id`; a request for the old "dumb" HTTP protocol (no `?service=`) |
| `404` | malformed, unknown or deleted repository ID; any other path |
| `413` | a clone or fetch request body over 64 MiB after decompression (it never holds a pack) |
| `415` | wrong `Content-Type` on a POST, or a `Content-Encoding` other than gzip |
| `500` | git-svc failed; the details are only in its log |

**Limits:**
- A push larger than 2 GiB fails with git's own message (`pack exceeds maximum allowed size`).
- One clone, fetch or push may run for 2 hours.
- No other timeout applies to bodies.

**Try it in the devcontainer** (no gateway, so set the user header yourself):

```sh
make run   # gRPC on :9090, HTTP on :9080
go tool -modfile=tools.mod grpcurl -plaintext -d '{"owner_id":"<owner-uuid>","name":"demo"}' \
  localhost:9090 git.v1.RepositoryService/CreateRepository
git clone http://localhost:9080/<repo-id>.git
cd <repo-id> && git commit --allow-empty -m first
git -c http.extraHeader="X-Git2-User-Id: <user-uuid>" push origin HEAD:refs/heads/main
```

## 🟢 NEW — `/healthz` and `/readyz` (Deploy's assumption B-04)

On the same port:
- `GET /healthz` answers `200 ok` while the process runs.
- `GET /readyz` answers `200 ok` when the database answers a ping, `503` otherwise.

The gRPC port still has the standard `grpc.health.v1.Health` service.

## 🟡 CHANGED — `git.v1.RepositoryPushed` is now written (for CI)

Each push over HTTP that updates at least one ref writes one `git.v1.RepositoryPushed` to `git_svc.outbox`, in the same format as the other events. Until the relay exists (WBS-1.3, W2), the rows wait there with `published_at` empty.

```json
{"repositoryId": "<repo-id>", "pusherId": "<user-id>", "occurredAt": "2026-10-31T10:15:02.120Z",
 "refUpdates": [
   {"ref": "refs/heads/main", "oldSha": "9fceb02d0ae598e95dc970b74767f19372d61af8",
    "newSha": "1d0faf0c5a4e3b2f0d9a8c7b6e5f4a3b2c1d0e9f", "forced": true},
   {"ref": "refs/tags/v1.0.0", "oldSha": "0000000000000000000000000000000000000000",
    "newSha": "1d0faf0c5a4e3b2f0d9a8c7b6e5f4a3b2c1d0e9f"}
 ]}
```

- **What a ref update means:** an all-zero `oldSha` means the ref was created, and an all-zero `newSha` means it was deleted. `forced` is `true` when the update rewrote history (not a fast-forward). Protobuf JSON leaves out `forced` when it is false.
- **What is left out:** refs the server rejected are not in the event, and a push that changed nothing writes no event.
- **Delivery:** the event is written just after git updated the refs, so it cannot share their transaction. In rare cases (git-svc stops, or its database fails, at that moment) a push has no event; git-svc logs every such case. An event never exists for a push that did not happen.

## ℹ️ FYI — Decisions behind this

[ADR 0012](../../../decisions/0012-git-over-https.md) covers:
- why git-svc runs git's own `upload-pack` and `receive-pack` instead of `git http-backend` or a Go implementation;
- how a `post-receive` hook reports the updated refs;
- why a push finishes even if the client disconnects;
- the limits;
- why there is no `git gc` during pushes.
