# Codeplane version notes — 2026-11-06

**Audience:** Deploy (gateway, Compose, Helm), CI, and their coding agents.
**Scope:** Git over HTTP on port 9080 now drops stalled clients and limits how much a client can make git-svc do. `RefUpdate.forced` in `git.v1.RepositoryPushed` can now be unknown. This changes what the [31 Oct note](../10/31_10.md) described; that note is corrected to match.

**Canonical reference:** [ADR 0012](../../../decisions/0012-git-over-https.md) for the HTTP side, and [proto/git/v1/events.proto](../../../../proto/git/v1/events.proto) for the event.
These are the source of truth; this note only summarizes the change.

**Breaking?** No. Git over HTTP and `RepositoryPushed` have not reached `main` yet, and nothing consumes `forced` so far.

---

## 🟡 CHANGED — New limits and answers on port 9080 (for the gateway)

| | Before | Now |
|---|---|---|
| Client sends nothing of its request body | could hold a git process for 2 hours | `408` after 5 minutes |
| Client stops reading the answer | could hold a git process for good | dropped after 5 minutes |
| Git operations at once | no limit | 32, then `503` with `Retry-After: 30` |
| Ref updates of one push, after decompression | no limit | 64 MiB (about 500,000 refs), then `413` |
| Ref advertisement (`GET .../info/refs`) | ended only when the client disconnected | 2 hours, like the other operations |

- The 5 minutes apply to one read or one write, not to a whole request. A slow client is fine as long as data moves, and a long clone or push is not cut off.
- They match the gateway's 5-minute idle timeout in `docs/api/gateway.md`.
- All answers are plain text, which git shows to the user as `remote: …`.

## 🟡 CHANGED — `RefUpdate.forced` can be unknown (for CI)

`forced` is now `optional bool`, with three states:

| JSON | Meaning |
|---|---|
| `"forced": true` | not a fast-forward: the update rewrote the ref's history |
| `"forced": false` | a fast-forward, or the ref was created or deleted |
| no `forced` key | git-svc could not tell: the objects are not commits, or the check ran out of time on a push that updated very many refs |

Before, a missing key meant `false`, and an update git-svc could not check was reported as `true`. In Go, use `GetForced()` when unknown may count as "not forced", and `Forced != nil` to tell the two apart.

The check for `forced` now has a time budget of its own, so a push that updates thousands of refs keeps its event.

## ℹ️ FYI — Events have no guaranteed order

The events of one repository can arrive in a different order than the pushes happened. `oldSha` and `newSha` show how the updates of a ref follow each other. [ADR 0012](../../../decisions/0012-git-over-https.md) explains why a stronger lock would not change this.
