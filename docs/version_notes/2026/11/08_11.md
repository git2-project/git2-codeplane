## 🟢 NEW — `events.v1.EventSink`

One RPC that every event consumer serves on its internal gRPC port. git-svc is the first producer; ci-svc's own relay will use the same contract (git2-runner ADR 0010).

```proto
service EventSink {
  rpc Deliver(DeliverRequest) returns (DeliverResponse);
}
// DeliverRequest: event_id, event_type, aggregate_type, aggregate_id,
// occurred_at, payload (protobuf JSON of the event_type message)
```

Go: `import eventsv1 "github.com/git2-project/git2-codeplane/gen/go/events/v1"` (available in the next tag, `v0.3.0`).

- Store the event and answer at once; do the work afterwards. The relay waits at most 10 seconds.
- Drop repeats by `event_id`: delivery is at least once.
- Decode `payload` with protojson into the message named by `event_type`. Do not compare it as text: field order and spacing can differ from what was written.

What your answer means to the relay:

| Answer | The relay |
|---|---|
| `OK` | counts the event as delivered to you |
| `INVALID_ARGUMENT`, `FAILED_PRECONDITION` | logs it at ERROR and never sends you that event again |
| any other code, including `UNIMPLEMENTED` | tries again later, with a pause that grows from 1 s to 1 minute, and never drops the event |

**`UNIMPLEMENTED` is retried, unlike the first table on git2-runner #33.** gRPC answers it when a server does not serve `EventSink` at all, so a consumer that is not ready yet loses nothing. For an event type you do not handle, answer `INVALID_ARGUMENT`.

## 🟢 NEW — the event relay in git-svc

- **Configuration:** `GIT2_GITSVC_EVENT_SINKS`, a comma-separated list of `host:port=type|type`, for example `ci-svc:9090=git.v1.RepositoryPushed`.
  - Each subscriber receives only the types it lists. The types must be ones git-svc writes: `git.v1.RepositoryCreated`, `git.v1.RepositoryDeleted` and `git.v1.RepositoryPushed`.
  - When it is empty, the relay is off and events wait in the outbox.
- **Polling:** every second, up to 100 events per batch, in outbox order. Order is still not guaranteed to the consumer (ADR 0012).
- **Marking:** an event is marked published once every subscriber of its type answered `OK` or refused it for good. An event nobody subscribed to is marked at once.
- **Retries:** while one subscriber fails, its later events wait for it. If a second subscriber of the same type already has the event, it receives it again and drops it by `event_id`.
- **Backlog:** events written before the relay first runs, including those from earlier test pushes, are delivered then.
