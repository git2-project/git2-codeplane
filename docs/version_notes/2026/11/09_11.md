# Codeplane version notes — 2026-11-09

**Audience:** Deploy (backup-svc, `git2ctl restore`, Compose, Helm) and their coding agents.
**Scope:** git-svc can copy every repository out as a Git bundle and put it back on a new server: the B-01 assumption of git2-deploy's `docs/design/assumptions.md`. Streaming RPCs also get a log line now.

**Canonical reference:** [proto/git/v1/bundle.proto](../../../../proto/git/v1/bundle.proto) and [ADR 0015](../../../decisions/0015-backups-as-git-bundles.md).
These are the source of truth; this note only summarizes the change.

**Breaking?** No. One new service; nothing existing changed.

---

## 🟢 NEW — `BundleService` (for backup-svc and `git2ctl restore` only)

It uses the same port and conventions as `RepositoryService` (`:9090`, repositories by ID). It reads every repository whatever its owner, so services that act for a user (gateway, dash-api) must never call it.

| RPC | What it does |
|---|---|
| `ListAllRepositories` | One page of the live repositories of every owner, sorted by ID. 100 per page by default, at most 1000. |
| `CreateBundle` | Server stream: one repository as a Git bundle of all its refs (`git bundle create --all`), in pieces of up to 64 KiB. |
| `RestoreBundle` | Client stream: puts a bundle back under the same repository ID. The first message carries `repository_id`; every message can carry data. |

**Empty repositories are zero bytes.** Git cannot bundle a repository that nothing was pushed to yet. Its `CreateBundle` stream is one message with `empty: true` and no data. Store an empty `repositories/<repo-id>.bundle` file, and restore it by sending `RestoreBundle` with no data.

**Consistency.** A bundle is the repository as it was when the bundle started. Pushes are not blocked meanwhile.

**Size.** The size is not known before the stream ends, and only a stream that ends with `OK` holds the whole bundle.

### Backup

After `pg_dump`, list with `ListAllRepositories` and bundle each repository:

```go
import gitv1 "github.com/git2-project/git2-codeplane/gen/go/git/v1"

bundles := gitv1.NewBundleServiceClient(conn)
stream, err := bundles.CreateBundle(ctx, &gitv1.CreateBundleRequest{RepositoryId: id})
if err != nil {
	return err
}
for {
	msg, err := stream.Recv()
	if errors.Is(err, io.EOF) {
		break // complete; an empty repository leaves the file empty
	}
	if err != nil {
		return err // discard the partial file
	}
	if _, err := file.Write(msg.GetData()); err != nil {
		return err
	}
}
```

```bash
grpcurl -plaintext -d '{"page_size": 1000}' <git-svc>:9090 git.v1.BundleService/ListAllRepositories
```

### Restore

Load the database first, so every repository's row exists again. Then send each bundle:

```go
stream, err := bundles.RestoreBundle(ctx)
// first message: {RepositoryId: id, Data: <first piece or nothing>}
// later messages: {Data: <next piece>}, with RepositoryId left empty
_, err = stream.CloseAndRecv()
```

If `Send` returns `io.EOF`, git-svc has already answered; `CloseAndRecv` returns its status. The restored repository keeps every ref of the bundle, and HEAD points to the row's default branch. A restore writes no event, so it starts no CI pipeline.

### Errors

| RPC | Code | When | What to do |
|---|---|---|---|
| all | `INVALID_ARGUMENT` | bad `repository_id`, negative `page_size`, bad `page_token` | fix the call |
| `CreateBundle`, `RestoreBundle` | `NOT_FOUND` | no live repository has this ID | backup: it was deleted after the listing, skip it. Restore: it was created after `pg_dump`, skip it |
| `RestoreBundle` | `INVALID_ARGUMENT` | `repository_id` set in a later message, or the data is not a whole bundle (cut short, damaged, not a bundle, no refs) | the backup file is broken; git-svc's log has git's reason |
| `RestoreBundle` | `ALREADY_EXISTS` | the repository already has its files, for example after a retry | count it as done |

### Between `pg_dump` and the bundles

| Case | After a restore |
|---|---|
| A repository created after `pg_dump` | It has a bundle but no row. `RestoreBundle` answers `NOT_FOUND`, and nothing is written to disk. |
| A repository deleted after `pg_dump` | It has a row but no bundle. git-svc lists it, but every read of it fails until it has files. `RestoreBundle` with no data gives it empty ones. |

## ℹ️ FYI — Streaming RPCs are logged

`CreateBundle`, `RestoreBundle` and `GetRawBlob` now write one `rpc` log line when they end, with method, code and duration, as unary RPCs already did.
