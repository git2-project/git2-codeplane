# Codeplane version notes — 2026-11-15

**Audience:** CI (ci-svc, git2-runner) and their coding agents.
**Scope:** git-svc can stream a commit's files as a tar archive, so a CI job can start with the pushed commit in `/workspace`. This is assumption A-04 of git2-runner's `docs/design/assumptions.md`, asked for in issue #13.

**Canonical reference:** [proto/git/v1/commit.proto](../../../../proto/git/v1/commit.proto) and [ADR 0016](../../../decisions/0016-commit-archives-for-ci-jobs.md).
These are the source of truth; this note only summarizes the change.

**Breaking?** No. One new RPC in `CommitService`; nothing existing changed.

---

## 🟢 NEW — `CommitService.GetArchive` (for ci-svc)

Same port and conventions as the other `CommitService` RPCs (`:9090`, repository by ID). It is a server stream:

| Message | Carries |
|---|---|
| first | `commit_sha`: the full SHA of the archived commit, and no data |
| every later one | `data`: the next piece of the tar archive, at most 64 KiB |

`ref` follows the same rules as in the other `CommitService` RPCs. ci-svc sends the pushed commit's full SHA (`new_sha` of the `RefUpdate`).

**What is in the archive:**

| | |
|---|---|
| Layout | The commit's files at the root, with no prefix: extract straight into `/workspace`. |
| Content | Exactly as committed. `.gitattributes` is not applied: files marked `export-ignore` are included, `export-subst` placeholders stay as they are, and line endings are not converted. |
| Modes | 0644; 0755 for executables and directories. |
| Symlinks | Symlinks. |
| Submodules | Empty directories. |
| Git LFS | Pointer files. |
| `.git` | None, so `git log` or `git describe` fail in a job (runner ADR 0004). |
| Times | The commit's committer time on every entry. |

**Only a stream that ends with `OK` holds the whole archive.** A tar cut between two files still reads as complete (Go's `archive/tar` returns `io.EOF`). Never start a job on a stream that failed.

**The content is untrusted.** The archive is whatever was pushed: an entry can be named `..`, and a symlink can point anywhere. Docker's copy into a container (`CopyToContainer`) keeps everything inside the container. Never extract the archive on the runner's host with your own loop.

**No size limit** in git-svc. Stop reading at ci-svc's own limit; git stops when the stream is canceled.

```go
import gitv1 "github.com/git2-project/git2-codeplane/gen/go/git/v1"

commits := gitv1.NewCommitServiceClient(conn)
stream, err := commits.GetArchive(ctx, &gitv1.GetArchiveRequest{RepositoryId: repoID, Ref: sha})
if err != nil {
	return err
}
for {
	msg, err := stream.Recv()
	if errors.Is(err, io.EOF) {
		break // complete
	}
	if err != nil {
		return err // discard what was received
	}
	if _, err := tmp.Write(msg.GetData()); err != nil {
		return err
	}
}
```

Try it in the devcontainer after a push. grpcurl prints `data` as base64:

```sh
go tool -modfile=tools.mod grpcurl -plaintext -d '{"repository_id":"<repo-id>","ref":"main"}' \
  localhost:9090 git.v1.CommitService/GetArchive
```

**Errors:**

| Code | When | What to do |
|---|---|---|
| `INVALID_ARGUMENT` | bad `repository_id` or `ref` | fix the call |
| `NOT_FOUND` | the repository or the ref does not exist (`repository not found`, `ref not found`), or the repository has no commits | the repository was deleted, or the commit is gone: fail the pipeline |
| any code after data arrived | git failed, or the stream was cut | discard the archive; retry or fail the job |
