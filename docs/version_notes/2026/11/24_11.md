# Codeplane version notes — 2026-11-24

**Audience:** Dash (dash-api) and its coding agents.
**Scope:** The gRPC services for merge requests: `DiffService` compares two refs, and `OperationService` checks and does merges. Issues #22 (contract), #23 (compare) and #24 (merge).

**Canonical reference:** [proto/git/v1/diff.proto](../../../../proto/git/v1/diff.proto), [proto/git/v1/operation.proto](../../../../proto/git/v1/operation.proto) and [ADR 0017](../../../decisions/0017-comparing-and-merging-branches.md).
These are the source of truth; this note only summarizes the change.

**Breaking?** No. Two new services; nothing existing changed.

---

## 🟢 NEW — `DiffService` and `OperationService` (for dash-api)

Same port and conventions as the other `git.v1` services (`:9090`, repository by ID). The table shows which call each dash-api operation needs:

| dash-api | git-svc |
|---|---|
| `GET /repos/{owner}/{repo}/compare?base&head` | `DiffService.CompareRefs(base, head)` |
| `GET .../merge-requests/{number}/diff` | `DiffService.CompareRefs(target branch, source branch)` |
| `MergeRequest.mergeable`, the merge box | `OperationService.CheckMerge(source, target)` |
| `POST .../merge-requests/{number}/merge` | `OperationService.MergeBranches(...)` |

dash-api checks the user's role, the branch rules and the approvals **before** calling `MergeBranches`; git-svc does not.

### `CompareRefs`: what a merge request would bring

The answer has the commits in `merge_base..head` and the changes from the merge base to `head`, the same as `git diff base...head`.

| Field | |
|---|---|
| `base_sha`, `head_sha`, `merge_base_sha` | Keep them with the merge request's diff, to anchor inline comments (FR-40) |
| `ahead_by`, `behind_by` | `behind_by > 0` means no fast-forward |
| `commits`, `commits_truncated` | Newest first, at most 250 |
| `stats`, `files`, `files_truncated` | Same `FileDiff` and limits as `GetCommit`: 300 files, 64 KiB per patch, 1 MiB in total |

- Nothing to merge is an answer: `ahead_by = 0` with no commits or files.
- `base` and `head` are required: branches, tags, full refs or full SHAs.
- No common history gives `FAILED_PRECONDITION`.

### `CheckMerge`: the merge box

The answer has `source_sha`, `target_sha`, `merge_base_sha`, `status`, `can_fast_forward`, and `conflicts` (paths, at most 100). The `status` is one of:

| `status` | Show |
|---|---|
| `MERGE_STATUS_CLEAN` | Merge button enabled. Offer fast-forward only if `can_fast_forward` |
| `MERGE_STATUS_CONFLICTS` | Disabled; list `conflicts` (FR-43) |
| `MERGE_STATUS_ALREADY_MERGED` | Nothing to merge |
| `MERGE_STATUS_UNRELATED` | Disabled; the branches share no history |

### `MergeBranches`: the merge

Request fields:
- `strategy`: `MERGE_STRATEGY_MERGE_COMMIT` (always a merge commit, like `--no-ff`), `MERGE_STRATEGY_SQUASH` or `MERGE_STRATEGY_FAST_FORWARD`.
- `expected_source_sha`: required. Send the source SHA that the reviewers saw. If the source moved, nothing is merged.
- `message` and `author`: required for merge commits and squashes. dash-api builds the message text.
- `committer`: optional.
- `merger_id`: the user's ID, which becomes the `pusher_id` of the `RepositoryPushed` event that ci-svc receives.

The answer has `old_target_sha` and `new_target_sha`.

**Errors:**

| Code | When | dash-api |
|---|---|---|
| `INVALID_ARGUMENT` | a bad ID, branch name, strategy, SHA, message or identity | `400`: fix the call |
| `NOT_FOUND` | the repository or a branch is gone | `404` |
| `FAILED_PRECONDITION` + `MergeError` | `CONFLICTS`, `FAST_FORWARD_IMPOSSIBLE`, `SOURCE_MOVED`, `ALREADY_MERGED`, `UNRELATED` | `409` with the reason; show the conflicts |
| `ABORTED` | the target kept moving | `409`: try again |

A retry after a timeout is safe. If the first call merged, the retry answers `ALREADY_MERGED`.

```go
import (
	"google.golang.org/grpc/status"

	gitv1 "github.com/git2-project/git2-codeplane/gen/go/git/v1"
)

ops := gitv1.NewOperationServiceClient(conn)
resp, err := ops.MergeBranches(ctx, &gitv1.MergeBranchesRequest{
	RepositoryId:      repoID,
	SourceBranch:      "feature",
	TargetBranch:      "main",
	Strategy:          gitv1.MergeStrategy_MERGE_STRATEGY_SQUASH,
	ExpectedSourceSha: reviewedSHA,
	Message:           "Merge branch 'feature' into 'main'\n\nSee merge request !12",
	Author:            &gitv1.CommitIdentity{Name: author.Name, Email: author.Email},
	Committer:         &gitv1.CommitIdentity{Name: merger.Name, Email: merger.Email},
	MergerId:          merger.ID,
})
if st, ok := status.FromError(err); ok && err != nil {
	for _, d := range st.Details() {
		if me, ok := d.(*gitv1.MergeError); ok {
			// me.GetReason(), me.GetConflicts(), me.GetSourceSha() ...
		}
	}
}
```

**Limits:**
- A commit message is at most 64 KiB, without NUL. A final line break is added if it has none.
- Names and emails are at most 255 bytes each, without `<`, `>` or a line break.
- If the target keeps moving, git-svc merges again up to three times before it answers `ABORTED`.

Try it in the devcontainer with grpcurl (`GIT2_GITSVC_DEV=true`):

```sh
go tool -modfile=tools.mod grpcurl -plaintext \
  -d '{"repository_id":"<repo-id>","source_branch":"feature","target_branch":"main"}' \
  localhost:9090 git.v1.OperationService/CheckMerge
```
